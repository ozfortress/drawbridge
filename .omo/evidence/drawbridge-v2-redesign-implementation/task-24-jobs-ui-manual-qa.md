The single failing verification is the claimed disconnect regression's discriminating power (A-24, A-25, A-27): reverting exactly the fix (disconnect handlers moved back after the `LISTEN` await, `raw.on('close')` and the late-acquisition release removed — the three elements the evidence names as the fix) while keeping the test-only `streamListen` seam leaves the suite green, 17/17 and 3/3 on repeat. - **repro:** `git worktree add --detach scratch 88a6a2a && cd scratch/v2 && pnpm install --frozen-lockfile`; replace `apps/web/src/routes/stream.ts` with `git show 19f729f:v2/apps/web/src/routes/stream.ts` plus only the four test-seam edits (`StreamListenerFactory` export, `StreamRouteDeps.listen`, `const listen = deps.listen ?? listenJobState`, call `listen(...)`); `TEST_DATABASE_URL=postgres://.../scratch pnpm exec vitest run apps/web/test/jobs.integration.test.ts -t "releases a listener acquired after the client disconnects"` → passes (should fail if the test pinned the fix). ## Findings

- **F-1 (harness — the reason for this verdict):** `apps/web/test/jobs.integration.test.ts` "releases a listener acquired after the client disconnects" does not pin the SSE disconnect fix. The evidence claim "a deterministic regression holds acquisition until after abort and proves closure" holds literally (it passes), but the claim that it "covers the same acquisition race" does not: the race it builds (acquisition held until after `abort()` is called) always completes before the disconnect is observable to the server, so pre-fix code survives it. Recommended fix (test-side only): complete the seam's acquisition only after the abort's close has been processed by the server (e.g., resolve the seam from a later task/event, not in the same turn as `abort()`), or drive the real `listenJobState` acquisition window; then the test fails on pre-fix code and passes on the fixed code, as the diagnostic run demonstrates (A-26).
- **F-2 (environment, not a product defect):** through `vite preview`'s `/api` proxy, destroying a browser document that holds a live EventSource leaves the upstream SSE socket — and its Postgres listener — held until a transport timeout (observed 1-4 minutes). SPA unmount closes promptly (verified 0→1→0). The product route releases in 2-4 ms whenever the transport close/error is delivered (direct sockets, all destroy modes, A-07), so this is the proxy not forwarding aborts promptly — worth noting for QA harnesses and for the production reverse-proxy contract (plan 02 §14: abort forwarding, read timeout > 15 s heartbeat). The first driver run's listener baseline (A-04 "FAIL S4-listeners-*" lines) is this artifact, not a leak; the clean cycle is A-06.
- **F-3 (pre-existing, outside todo 24's diff):** `POST /api/v1/leagues` with an existing `(guildId, citadelLeagueId)` pair returns 500 from the `leagues_guild_citadel_key` unique violation instead of a 4xx (observed in `qa-server2.log`). This is the todo-11 league API surface, untouched by this commit; noted for follow-up only.
- **F-4 (incident during verification):** Postgres 5433 (Docker Desktop compose project `drawbridge-v2-dev`) stopped between 07:17:16 and 07:20:22 UTC mid-run, before the first targeted integration rerun — that run skipped 17/17 and was discarded as invalid (A-29; skipped ≠ passing). Restored with `docker compose -f compose.dev.yaml up -d postgres` (named volume persisted) and re-ran: targeted suite 17/17 (A-03), probes (A-07), clean browser window (A-06). The 486/486 full suite (A-01) completed before the outage and is valid. Also note two first-driver measurement defects corrected in the second driver: the mobile scroll assertion measured the `<table>` instead of its `.table-wrap` scroll container (A-06 confirms 594>358 inside the wrapper at page width 390), and the listener baseline was polluted per F-2.

**Prose-only claims audit:** all evidence claims substantiated except the regression-coverage claim in F-1. No client-only gating found (SE-13). No product-side leak on disconnect found (AD-07). No screenshot misrepresents its state (SE-14).
